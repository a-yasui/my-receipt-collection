# 要件ファイル：Hono.js + Vue.js3 + Cloudflare D1による料理レシピ管理サイト構築

## 1. プロジェクト概要

料理レシピ管理サイトを以下の技術スタックで新規構築する：
- **バックエンド**: Hono.js (Cloudflare Workers)
- **フロントエンド**: Vue.js3
- **データベース**: Cloudflare D1 (SQLite)
- **画像ストレージ**: Cloudflare R2
- **ホスティング**: Cloudflare Pages & Workers

## 2. 機能要件

### 2.1 レシピ管理機能
1. **基本CRUD操作**
   - レシピの作成・読取・更新・削除
   - 入れ子構造のレシピサポート（ソース、マリネなどのサブレシピ）
   - parent_recipe_idによる階層構造の管理

2. **レシピ構成要素**
   - タイトル、説明文
   - 調理時間、分量
   - 画像（オプショナル）

### 2.2 材料管理機能
1. **材料入力**
   - 材料名、分量、単位の入力
   - サブレシピの参照機能（sub_recipe_id）
   - ドラッグ&ドロップによる並び替え

2. **効率化機能**
   - お気に入り材料機能（頻繁に使う材料の登録）
   - オートコンプリート機能
   - 一括入力対応

### 2.3 調理手順管理
1. **手順入力**
   - ステップごとの説明文
   - 調理時間の設定（タイマー機能用）
   - 画像添付（オプショナル）
   - ドラッグ&ドロップによる順序変更
   - 各手順で使用する材料の関連付け（例：「玉ねぎを炒める」手順に「玉ねぎ」を関連付け）

### 2.4 タグ・検索機能
1. **タグ管理**
   - レシピへの複数タグ付け
   - タグの作成・編集・削除

2. **検索機能**
   - レシピ名での検索
   - タグによるフィルタリング
   - 材料名での検索
   - 調理手順内のテキスト検索

### 2.5 ユーザビリティ機能
1. **表示機能**
   - レシピ詳細表示
   - 印刷用レイアウト
   - レスポンシブデザイン
   - 手順ごとの使用材料ハイライト表示

2. **操作性**
   - キーボードショートカット
   - 一時保存機能
   - 元に戻す/やり直し機能

### 2.6 API構造
RESTful APIエンドポイント：
- `/api/recipes` - レシピCRUD
- `/api/ingredients` - 材料管理
- `/api/steps` - 手順管理
- `/api/steps/{id}/ingredients` - 手順に関連する材料の管理
- `/api/tags` - タグ管理
- `/api/favorite-ingredients` - お気に入り材料
- `/api/images/upload` - 画像アップロード
- `/api/images/{id}` - 画像取得・削除
- `/api/health` - ヘルスチェック

## 3. 技術要件

### 3.1 バックエンド (Hono.js)
- **フレームワーク**: Hono.js
- **実行環境**: Cloudflare Workers
- **API設計**: RESTful API
- **バリデーション**: Zod
- **エラーハンドリング**: 統一的なエラーレスポンス形式

### 3.2 データベース (Cloudflare D1)
- **テーブル設計**:
  - `recipes` - レシピ情報（親子関係あり、画像URL含む）
  - `ingredients` - 材料情報
  - `steps` - 調理手順（画像URL含む）
  - `step_ingredients` - 手順・材料関連（手順で使用する材料の関連付け）
  - `tags` - タグマスタ
  - `recipe_tags` - レシピ・タグ関連
  - `favorite_ingredients` - お気に入り材料
  - `images` - 画像メタデータ（R2オブジェクトキー、サイズ情報等）

### 3.3 フロントエンド (Vue.js3)
- **フレームワーク**: Vue.js 3 + Composition API
- **ビルドツール**: Vite
- **状態管理**: Pinia
- **ルーティング**: Vue Router
- **UIライブラリ**: Tailwind CSS
- **コンポーネント設計**: 
  - 単一ファイルコンポーネント（SFC）
  - 再利用可能なコンポーネント設計

### 3.4 画像ストレージ (Cloudflare R2)
- **用途**: レシピ画像、手順画像の保存
- **アップロード処理**: 
  - Workers経由での画像アップロード
  - 画像の圧縮・リサイズ処理
  - 複数サイズの生成（サムネイル、中サイズ、オリジナル）
- **配信**: 
  - CDN経由での高速配信
  - 適切なキャッシュ設定
- **管理**: 
  - 画像URLのDB保存
  - 不要画像の定期削除

### 3.5 開発・デプロイ環境
- **開発ツール**: 
  - Wrangler CLI (Cloudflare Workers開発)
  - Vite (フロントエンド開発)
- **デプロイ**:
  - Cloudflare Pages (フロントエンド)
  - Cloudflare Workers (API)
- **CI/CD**: GitHub Actions

## 4. 非機能要件

### 4.1 パフォーマンス
- ページロード時間: 2秒以内
- API レスポンス: 200ms以内
- エッジでの実行による低レイテンシ

### 4.2 セキュリティ
- HTTPS通信の強制
- 入力値の適切なバリデーション
- SQLインジェクション対策
- XSS対策
- 画像アップロードの検証（ファイルタイプ、サイズ制限）
- R2への直接アクセス制限（署名付きURL使用）

### 4.3 可用性・信頼性
- Cloudflareのグローバルネットワーク活用
- エラー時の適切なフォールバック
- データの定期バックアップ

### 4.4 保守性
- コードの可読性重視
- 適切なコメント・ドキュメント
- テストコードの整備

## 5. 制約事項

### 5.1 Cloudflare Workers制約
- 実行時間制限: 10ms (Bundled) / 50ms (Unbound)
- メモリ制限: 128MB
- スクリプトサイズ: 1MB (圧縮後)

### 5.2 Cloudflare D1制約
- データベースサイズ: 10GB
- 行サイズ制限: 1MB
- クエリ実行時間制限

### 5.3 Cloudflare R2制約
- オブジェクトサイズ: 最大5TB/オブジェクト
- リクエスト制限: 1000リクエスト/秒
- ストレージコスト: $0.015/GB/月
- 帯域幅: 無料（Cloudflare内）

### 5.4 開発期間
- MVP（最小機能製品）の早期リリース
- 段階的な機能追加
